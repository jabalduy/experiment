# Experiment — учебное исследование влияния рейтинга

Go + PostgreSQL. **Один и тот же тест** для двух условий: `ranking` (предупреждение о соревновании до теста и рейтинг после завершения) и `control` (без рейтинга). Назначение группы происходит на сервере, поочерёдно с балансировкой размеров групп. Студент не выбирает условие самостоятельно.

## Запуск

1. Установить Go 1.23+ и Docker.
2. `docker compose up -d`
3. `export DATABASE_URL='postgres://experiment:experiment@localhost:5432/experiment?sslmode=disable'`
4. `go mod tidy && go run .`
5. Открыть http://localhost:8080

Вопросы: `quizzes/experiment.json`. После изменения вопросов перезапустите приложение. Не меняйте тест после начала реального сбора данных.

## Принцип эксперимента

- Студент вводит имя и соглашается на участие. Создаётся одна серверная попытка с уникальным токеном в HttpOnly cookie.
- Группа назначается сервером. В ranking до начала вопросов показывается предупреждение о соревновании, а таблица результатов участников группы появляется **только после завершения**. В control рейтинг не показывается ни во время теста, ни после.
- По завершении сохраняются ответы по каждому вопросу, правильность, время ответа от отображения вопроса (из браузера, вспомогательная метрика), серверное время старта и завершения и итоговый балл.
- Результаты доступны в CSV через `/admin/export?key=...`, если установлен `ADMIN_KEY`. Не делитесь этим ключом и не размещайте его в публичных URL/скриншотах; для реального использования лучше добавить защищённую админ-аутентификацию.
- Обновление страницы не создаёт новую попытку в том же браузере. Без логина или университетского ID невозможно гарантировать, что один человек не участвует повторно с другого браузера.

## Методологические ограничения

Это пилотная реализация. **Показываемый рейтинг сам по себе не измеряет напряжение**. Для проверки гипотезы добавьте одинаковую для обеих групп краткую шкалу субъективного напряжения до теста и после ответов (до показа итогов), а также зафиксируйте первичный исход (например, точность) и план анализа до начала сбора данных. Две группы должны проходить идентичные вопросы в одинаковом порядке; различаться должно только наличие рейтинга. При малой выборке или неравных условиях нельзя делать причинные выводы. Первые участники ranking могут увидеть пустой рейтинг — это потенциальный конфаундер, предусмотрите предварительную процедуру заполнения рейтинга или зафиксируйте это ограничение.

## Переменные окружения

- `DATABASE_URL` — строка подключения PostgreSQL (обязательная).
- `PORT` — порт (по умолчанию 8080).
- `ADMIN_KEY` — ключ для CSV-экспорта; без него экспорт отключён.

В продакшене используйте HTTPS, секреты окружения, ограничение доступа к CSV и настройте резервное копирование PostgreSQL. Демо-учётные данные из compose **только для локальной разработки**.


## Протокол пилотного исследования

**Гипотеза:** отображение таблицы лидеров во время тестирования связано с изменением субъективного напряжения и может влиять на точность ответов.

**Условия:** один набор вопросов, одинаковый порядок, одинаковые инструкции; отличается только отображение рейтинга. Группы распределяются сервером с балансировкой численности.

**Измерения:** `baseline_stress` (до теста), `stress` (после ответов, до результата), `stress - baseline_stress` (изменение), `score` (точность), `ranking_seen` (был ли реально показан хотя бы один результат другого участника), `started_at` и `finished_at` (длительность). Клиентское `elapsed_ms` сейчас означает время от загрузки страницы до выбора ответа, а не время решения отдельного вопроса; его нельзя интерпретировать как чистое время ответа.

**Основное сравнение:** различие среднего изменения напряжения между назначенными группами (intention-to-treat). **Вторичное:** различие средних баллов и длительности. Отдельно описать долю участников ranking, завершивших тест до появления других результатов; анализ только увидевших рейтинг может быть смещённым, поэтому не подменяет основное сравнение.

**Ограничения:** назначение сбалансировано по числу регистраций, а не по числу завершений. Участники могут повторно участвовать с другого браузера. Рейтинг открывается только после завершения; воздействие во время ответов — ожидание соревнования, а не просмотр чужих баллов. Имена-псевдонимы в рейтинге могут косвенно раскрывать личности. Получите добровольное информированное согласие, не собирайте лишние персональные данные и заранее определите сроки хранения/удаления.

**До основного сбора:** провести пилот, проверить предупреждение, отсутствие рейтинга до завершения, таблицу после завершения и CSV, выбрать число участников, зафиксировать гипотезы, исключения и статистический план. Не добавлять фиктивных участников в рейтинг без явного информирования: это меняет экспериментальное воздействие.

## Панель администратора

Установите `ADMIN_KEY` и откройте `GET /admin`, передав заголовок `X-Admin-Key: <ключ>` (например, через curl или HTTP-клиент). Панель показывает численность групп, число завершивших, средний балл, среднее изменение напряжения и среднее время прохождения. CSV экспортируется через `/admin/export` с тем же заголовком. Не размещайте ключ в публичных ссылках.

**Важное изменение протокола:** экспериментальная группа получает предупреждение о соревновании перед вопросами, но рейтинг видит **только после** завершения теста. Контрольная группа не получает предупреждение и не видит рейтинг. Следовательно, исследуется влияние ожидания рейтинга/соревнования, а не влияние наблюдения рейтинга во время теста. Поле `ranking_seen` из ранней схемы теперь не используется как индикатор воздействия.


## Этап 1 — зафиксированная механика

После регистрации и исходной оценки напряжения участник попадает на **отдельную страницу инструкции** `/briefing`. Только экспериментальная группа видит сообщение о соревновании. Кнопка «Начать отвечать» записывает `test_started_at` в PostgreSQL; именно от этого момента считается продолжительность теста. До нажатия кнопки `/test` и `/finish` недоступны. Обновление страницы не перезапускает время. Таблица лидеров открывается исключительно после завершения теста.

Поле `started_at` — момент регистрации, `test_started_at` — начало ответов. В CSV доступны оба времени. Схема обновляется автоматически через `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`. **Старые попытки, созданные до добавления этапа инструкции, могут иметь пустой `test_started_at`; перед реальным исследованием используйте чистую базу.**

Необходимо интеграционное тестирование с PostgreSQL и двумя браузерными сессиями перед сбором данных. Текущий этап не включает полноценную защиту от повторного участия с разных устройств, поскольку регистрация без учётных записей не позволяет гарантировать уникальность личности.


## Этап 2 — интерфейс участника

Интерфейс адаптирован под мобильные устройства и компьютеры. Стили вынесены в `static/style.css`. Страницы: регистрация с исходной оценкой напряжения, отдельная инструкция для назначенной группы, тест с индикатором прогресса, заключительная оценка напряжения и итоговый экран. Таблица лидеров показывается только экспериментальной группе после отправки ответов. Ответы и правильные варианты не раскрываются в HTML до отправки.

Визуальная проверка в реальном браузере и интеграционное тестирование с PostgreSQL запланированы на финальный этап. Для использования в эксперименте следует также утвердить окончательный текст информированного согласия.


## Этап 3 — административная аналитика

Откройте `/admin`. Браузер запросит учётные данные HTTP Basic Auth: **имя пользователя произвольное, пароль равен значению `ADMIN_KEY`**. Также поддерживается заголовок `X-Admin-Key`. Не используйте панель без HTTPS на публичном сервере: Basic Auth передаёт пароль в кодировке Base64, а не шифрует его. Если `ADMIN_KEY` не задан, доступ закрыт.

Панель показывает количество зарегистрированных и завершивших по группам, средние баллы, напряжение до/после, изменение напряжения и среднее время ответов. Есть диаграмма средних баллов, таблица правильности по каждому вопросу и список последних 200 участников. Показатели по вопросам и средние значения вычисляются для завершённых попыток; пустые группы помечаются отсутствием данных. Время считается от `test_started_at`. Данные CSV доступны на `/admin/export` с той же авторизацией.

Графики и таблицы носят **описательный** характер и не означают статистической значимости. Для научных выводов потребуются заранее выбранные гипотезы и статистические тесты. Проверка сборки, реальной базы данных и браузерного сценария остаётся задачей финального этапа.
